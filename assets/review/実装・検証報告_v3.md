作成日：2026年10月16日（日本時間）
基準：harahettarou/fullpuri main `2418d0f5fd7627c556105d5be7617f57d9c6355a`。

## 実装内容

No.全体・ページ・赤／緑／オレンジ語句・選択した黒文字・手動範囲へ、復習チェックから独立した文字入力メモを追加しました。1対象1メモ、最大6000文字です。語句タップ時の操作、メモアイコン、専用一覧、本文・語句検索、対象・No.絞り込み、作成日／更新日／No.順、編集・削除、元位置リンクと強調表示を実装しています。

GitHub OAuthと既存ログインを共有し、Cloudflare Workerの `/notes`・`/note-operations` で読み書きします。D1の `notes` に現在の本文・対象・作成日・更新日・版番号・削除情報、`note_operations` に二重送信防止用の操作を保存します。サーバーで認証した所有者IDを必ず適用し、リクエスト中の自己申告IDは採用しません。

端末のIndexedDBに利用者別のキャッシュと未送信操作を保持します。端末内保存だけで完了にせず、サーバー保存状況を表示します。オフライン後の再送、同じ操作の二重適用防止、版の不一致時の競合確認を実装しました。編集中のメモが同期で上書きされる場合も、入力欄は保持したまま保存を止めます。

同じ元画像座標を使い、既存の復習対象と同様の安定IDで対応します。登録済みの座標はOCR更新時に自動移動しません。黒文字は既存方式と同じく、選んだ文字列とOCR行の座標を保持します。より厳密な位置は手動範囲で指定できます。

## ファイル

- 既存55 HTML：追加済み復習機能のCSS・JS参照をv3へ変更するだけ。元の閲覧処理は保持。
- `pages/review.html`：メモ一覧リンクとv3読込。
- `pages/notes.html`：メモ管理ページ。
- `core_v3.js`：既存復習処理＋メモ未送信時のログアウト防止。
- `viewer_v3.js`・`navigation_v3.js`・`manager_v3.js`・`review_v3.css`：メモ操作・入口・表示。
- `notes_core_v3.js`：アカウント別メモキャッシュ・保存キュー・同期・競合解決。
- `note_editor_v3.js`：入力・編集・保存・削除・未保存確認。
- `notes_manager_v3.js`：一覧・検索・絞り込み・元位置・競合確認。
- `server/worker_v3.mjs`・`wrangler_v3.jsonc`：復習とメモのAPI。
- `server/migrations/0002_notes_v3.sql`：既存DBへの追加のみ。
- `tests/*_v3*`：検証コードと結果。ファイル別ハッシュは変更ファイル一覧_v3.json。

## 検証

本番SQLを適用したローカルSQLite、仮想DOM・IndexedDBで自動テスト26件成功。登録・編集・削除・再作成、7種の対象、別クライアントへの同期、オフライン→再読込→再送、競合の検出と本文統合、ログアウト時の端末キャッシュ削除とサーバー保持、別ユーザーの閲覧・削除禁止、本文の文字数制限、HTML文字列の安全な表示、一覧検索、範囲メモ、アイコン表示切替、元位置リンク・強調、編集中の本文保護を確認。

既存の復習登録・完了・回数・日時・履歴・認証・競合・OCR黒文字選択・範囲指定・管理画面に関する19件も、v3プログラムで引き続き成功しました。メモの保存・削除が復習状態と回数を変えないことを確認しました。

既存55 HTMLは参照バージョンの変更を戻すと基準コミットと一致します。画像・OCR・地図データは更新ZIPに含みません。JPEG再圧縮・解像度変更はありません。

## 未検証・制限

- このv3のCloudflare本番適用、実GitHubログインを使ったメモ保存・端末間同期は未実施。既存v2の復習保存・同期は利用者確認済みですが、メモの本番確認とは区別します。
- PC・スマホ・iPadのメモ機能の実ブラウザ描画・タッチ・ズーム・ピンチは未検証。仮想DOMの成功を実機確認として扱っていません。
- 本番での別アカウント間分離は未確認。サーバーの所有者制限は自動テスト済みです。
- アイコンは原文や他の対象と重ならない余白に配置し、密な箇所では省略します。メモ一覧や語句一覧から操作できます。
- 本文を入力しただけではサーバー保存しません。「メモを保存」を押す方式です。
- 大量メモ時の実端末性能は未計測。一覧は60件ずつ表示します。

## 外部設定

新しいアカウント・サービス・秘密情報は不要。既存D1への追加SQL実行、Workerコード差替え、GitHub Pagesへの差分適用が必要です。既存DBの削除・再作成は不要です。
