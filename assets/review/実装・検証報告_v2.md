## 認証・保存・同期

- GitHub OAuthの認証結果をWorkerで確認し、GitHubの数値IDを所有者キーとします。
- サーバー発行の30日有効セッションでAPIを認証し、全ての一覧・履歴・変更処理に所有者条件を付けます。利用者がリクエストにユーザーIDを加えても採用しません。
- OAuth state、PKCE、2分で期限切れになる一度限りの交換券を使用します。GitHubのアクセストークンはブラウザに渡さず、D1へ保存もしません。
- D1内のセッショントークン・交換券・stateはSHA-256でハッシュ化して保存します。GitHub Client SecretはWorkerの秘密設定にだけ置きます。
- GitHub PagesとWorker間はBearer認証を使用し、第三者Cookieには依存しません。APIは固定したサイトのOriginを検証します。
- 永続保存の本体はD1です。端末のIndexedDBは認証済みの利用者ごとのキャッシュと未送信操作の保管用です。localStorageは表示設定のみに使用します。
- フォーカス復帰・オンライン復帰・再同期操作・表示中30秒ごとの照会で同期します。
- 一意な操作IDで再送を処理し、データベースの同一トランザクション内で状態・回数・履歴を更新します。
- バージョン番号が一致しない変更は409として拒否します。無言で上書きせず、利用者に採用する変更を確認します。

## 履歴と座標

`entries` に現在の状態・日時・回数・版番号、`history` に登録・完了・再登録・削除のイベントを記録します。`operations` は再送の二重適用防止に使います。

完了→再登録では回数・最終復習日時・過去の完了履歴を保持し、現在の完了日時だけ解除します。同じ操作の再送や、すでに完了した項目への完了操作では回数は増えません。削除は一覧から除外する方式で、競合防止用の削除情報と履歴をサーバーに残します。

No.・ページキー・種類・色・元画像に対する正規化座標からIDを作成します。黒文字のみ、同じOCR行から別々に選んだ文字を区別するため利用者の選択文字列も使います。通常のOCR文字列の修正は色付き対象のIDへ影響しません。登録後の座標を自動的に書き換えません。

## 未完成・未検証と制限

1. Cloudflare Worker・D1の初期設定とWorker公開は確認済みです。`config_v1.js` のAPI URLを設定しました。古プリ側へこのZIPを適用・公開し、本番ログインと保存・同期を確認する必要があります。
2. PC・スマホ・iPadの実機確認は全て未実施です。OS／ブラウザごとのIndexedDB、画面幅、タッチ、ピンチ、長押しの確認が残っています。仮想DOMの成功を実機成功とは扱っていません。
3. 本番のGitHubログインからD1への保存、別の実端末からの再取得は未検証です。D1でCASE式を括弧で囲まない初期SQLが incomplete input となったため修正し、利用者のConsole実行結果でテーブル・トリガーの作成を確認しました。実際の保存処理は本番未検証です。
4. 直接表示では原文・他のボタン・OCR行と重ならない余白を探します。余白がない対象のボタンは表示せず、文字のタップか語句一覧へ誘導します。全語句のボタン常時表示を保証する実装ではありません。
5. 黒文字は利用者が選んだ文字列を個別登録できますが、保存座標は元のOCR行の範囲です。単語だけを厳密に囲みたい場合は手動範囲指定を使います。
6. 同じ画像への同じ種類・色・座標の登録はIDで重複を防ぎます。別の手動操作で少し違う範囲を囲んだ場合は別項目として扱います。
7. OCRに誤りがある場合、参考表示もそのまま崩れる可能性があります。位置で登録でき、OCR本文には変更を加えていません。
8. 大幅な画像差し替え・回転・切り抜きでは座標の再確認が必要です。曖昧な対象への自動移動は行いません。
9. 表示速度・大量件数時の実端末性能は未計測です。対象データはNo.単位で読み込み、復習管理の表示は60件ずつ追加します。
