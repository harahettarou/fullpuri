# 既存の古プリ表示に編集側を揃える v25

基準はGitHub main ea7025e47a8a462b9651fef6bf8c48ac06d77a0fです。
v23・v24の適用は不要です。このZIPだけを適用してください。

## 操作と表示

既存の通常No.ページと同じく、本文の枠は答えを表示する範囲です。
答えは枠の中央へ配置し、指定文字サイズを上限に、枠の幅・高さに収まるサイズへ自動調整します。
本文枠と解答欄を囲み、文字・文字サイズを入力して登録します。既存項目は選択して囲み直し・位置・幅・高さ・文字を変更できます。
この方式を編集画面、新たに追加した番号対応、明示的に文字・サイズ・本文枠を編集した既存項目の公開表示に使います。
緑マーカーなど別の編集を保存しただけの場合、変更していない既存番号の表示は元のままです。

元のPAGES・画像・PDF・文字列・指定文字サイズ・座標・通常表示の描画処理は変更していません。
38HTMLはviewerの参照先だけの変更です。既存の復習・メモ・編集データや履歴も変更しません。

## 適用

ZIPを解凍せず `_update_inbox` に1個だけ入れ、更新BAT → GitHub DesktopのCommit → Push。公開サイトを再読み込みします。
Cloudflare Workerの差し替え・SQL実行・外部サービス設定は不要です。

## ファイルと検証

通常No.ページ38HTMLのviewer参照先、assets/classic/editor_v25.js・correction_v25.js・number_layout_v25.js、assets/review/viewer_v25.js、ブラウザ検証と結果、本手順。
実際のNo.7の既存描画関数と編集用描画関数を画素単位で比較し、一致を確認しました。狭い枠と長い文字列でも、枠内への自動調整・中央配置・枠外に出ないことを確認しています。
PC・スマホ・iPad相当の範囲編集、タッチ拡大・移動、モード切り替え、番号対応の追加・既存編集、保存・公開、再読み込み復元、復習登録のブラウザ検証も成功しました。
テストはローカルのテスト用セッション・SQLiteで行い、本番データは操作していません。実機Safari、Windowsの更新BAT、本番適用後は未検証です。
