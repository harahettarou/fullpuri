# 古プリ本体の編集・連続復習 v18

GitHub main の d9ac4a0b844cfc9944ea6caf0e092760ce3bea32（v17適用済み）を基準に作成。
原本画像・PDF・既存のページデータを加工せず、管理者の編集を別に保存して重ねる更新です。

## 今回必要な設定

今回はフロント画面だけでなく、既存のCloudflare D1にSQLを追加し、同じWorkerをv18へ更新します。
新しいアカウント契約・新しいDB・R2の追加設定は不要です。
既存の DB / MATERIALS_BUCKET のバインディングと、ADMIN_USER_IDS・Google/GitHub認証設定・シークレットは維持してください。

### 適用の順番

1. ZIPを解凍せず `_update_inbox` に1個だけ入れ、`更新パックを適用.bat` を実行します。この時点ではまだPushしません。
2. ローカルの次のファイルをメモ帳などで開き、全文をコピーします。
   `assets/review/server/migrations/0006_classic_edits_v18.sql`
3. Cloudflare → D1 → 既存の `fullpuri-review` → ConsoleでSQLを実行します。
   「This query returned no data.」でもエラーがなければ正常です。
   `classic_edits` / `classic_edit_operations` / `classic_edit_history` の3テーブルと、`classic_edit_guard` / `classic_edit_apply` の2トリガーが追加されます。
4. ローカルの `assets/review/server/worker_v18.mjs` を開き、全文をコピーします。
5. Cloudflare → Workers & Pages → 既存の `fullpuri-review` → Edit codeでコード全体を置き換えてDeployします。変数・秘密情報・DB/R2の設定を削除しないでください。
6. `https://fullpuri-review.niwatorikounotori.workers.dev/health` を開き、`version:18` と、features内の `classic-editing` を確認します。
7. GitHub DesktopでCommit → Push。公開サイトを再読み込みします。

SQLは追加のみで、既存の復習・メモ・認証・教材テーブルは削除・変更しません。
このZIPを適用する処理自体には、CloudflareのSQL実行やWorkerのデプロイは含まれません。

## 古プリを編集する

1. 管理者アカウントで通常のNo.ページを開きます。
2. 表示設定付近の「古プリを編集」を押します。
3. 編集メニューから文字・緑マーカー・赤文字を隠す範囲・原文を白く覆う範囲を追加できます。
4. 文字は入力・色・大きさを指定し、「配置する」でPDF画像上をタップ、またはドラッグします。
5. 追加済みの一覧から、文字の修正、位置・大きさの変更、削除を選べます。元に戻す／やり直すも使えます。
6. 「下書きを保存」→「表示を試す」→「公開する」。下書きの保存だけでは他の人の画面に反映されません。
7. 「編集を終了」で閲覧に戻ります。公開後も同じ手順で再編集できます。

管理者は既存の `ADMIN_USER_IDS` で判定し、API側でもセッションと権限を検証します。一般ユーザーは編集・下書き・履歴へアクセスできません。
公開した編集は、未ログインを含む通常のNo.ページの閲覧者に表示します。

### 既存項目と原本の扱い

- 既存の緑マーカーは一覧から移動・大きさ変更・非表示／復帰ができます。
- データで登録された既存オレンジ文字も、文字・大きさ・位置・表示／非表示を変更できます。
- 画像に焼き込まれた文字・マーカーの色そのものは変更しません。必要なら「原文を白く覆う」＋文字追加を使います。白く覆う範囲は表示スイッチOFFでも覆います。
- 原本の既存赤文字隠しは維持し、追加の赤い範囲で調整します。元から焼き込まれた赤文字を自動抽出・直接編集する機能は追加していません。
- 追加した赤・緑・オレンジ文字は復習チェックの対象にもなります。黒文字へチェックボタンを大量に自動配置する処理は追加しません。
- 変更・削除した項目に既に付いている復習・メモは、保存済みの元座標と履歴を維持します。文字を動かしても個人の既存チェックを勝手に移動・削除しません。
- 正規412ページの構成・元の編集データとの一致を確認します。情報が違う古い複製HTMLでは、誤った位置に編集を適用せず正規ページへのリンクを表示します。
- 今回の公開編集は通常のNo.ページに反映します。世紀別の切り出し画像や総合年表などの集約表示を再生成する処理は含みません。既存の集約表示自体は変更していません。

## 復習管理に戻らず進む

### 古プリからそのまま始める

「復習」→「要復習を続けて見る」で開始できます。
登録済み語句の操作画面からは「この項目から続けて復習」。
追加教材では下部の復習欄にある「続けて復習」を使います。

### 管理画面の条件を引き継ぐ

復習管理で状態・対象・No.・並び順を選び、「この一覧で復習を始める」を押します。
各項目の「元の位置を開く」からも、同じ絞り込み・並び順で続けられます。表示先頭60件だけでなく条件に合う全項目が対象です。

### 閲覧画面の操作

- 「前の復習」「次の復習」で、完了にせず移動できます。
- 「復習完了して次へ」で、保存を確認してから次へ進みます。
- 同じページ内の別語句、別No.・別単元、追加教材の間を移動できます。移動先では登録した位置を強調します。
- 単なる表示や移動では復習回数を増やしません。完了済み項目を戻って見ても再加算しません。
- 最後の項目では完了を保存してその場に留まります。未完了を飛ばした場合に全件完了とは表示しません。
- 通信失敗時は元の項目に留まり、変更を端末に残して「保存を再試行」を表示します。
- 「閉じる」で連続復習の操作欄を閉じられます。

順序用のID一覧は端末のIndexedDBでログインユーザー別に保持します。URLには語句本文を入れません。
同じ端末では再読み込み・ページ移動後も継続できます。別端末で同じ「途中位置」を自動再開する機能は今回追加していません。
個々の登録・完了・回数・復習日・履歴は、従来通りサーバーに保存・同期されます。

## 保存・復旧

編集はD1の `classic_edits` にページ別の下書きと公開版を分けて保存します。
公開前の入力・未配置文字・未送信操作は、端末のIndexedDBに管理者ユーザー別・ページ別で退避し、再読み込み後に復元確認を出します。
「編集を書き出す」でJSONの控えも保存できます。

保存操作には操作IDと版番号を付け、SQLトリガーで内容変更と監査履歴を同時に記録します。
通信の応答が消えても同じ操作IDで再送し、保存・履歴が重複しないようにしています。
別端末と競合した場合は入力を残し、「競合・保存内容を確認」から書き出し／入力を保持して最新版に合わせる／端末の変更を破棄して最新を読む、を選べます。
編集の保存・公開・取り消し履歴は `classic_edit_history` に公開時のスナップショットと操作日時・実行者IDを保持します。復習履歴は既存のhistoryテーブルを継続使用します。

自動テスト100件成功。既存の認証・権限・復習履歴・個人／共通メモ・教材APIの回帰テストを新Worker v18へ接続して実行。

既存緑・オレンジの編集、未配置文字の再読み込み復元、応答消失後の再送で履歴が増えないこと、競合からの明示的な復旧も確認。
連続復習では、管理画面からの順序保持、古プリ上での直接開始、追加教材から古プリ、同一ページ内の別項目、別単元への移動、位置の強調、完了回数・履歴、保存失敗時に移動しないことと再送を確認。

検証はテスト用セッション・SQLite・保存先を使い、本番の教材・復習・メモは操作していません。
iPhone・iPad・Androidの実機、Safari、本番のSQL実行・Worker更新・ZIP適用後の動作は未検証です。
