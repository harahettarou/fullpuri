# 教材ライブラリ v15

基準: harahettarou/fullpuri の main、cbe4b0f7a5a0ff9dec09c385178f90be36485b6a（2026-10-18取得）。
既存の世界史プリントとは別のページに追加。GitHub Pagesの静的構成と、既存のGitHub／Google認証を使用する。

## 追加内容

- `pages/materials.html`: 教科・フォルダー・教材名で探せる教材一覧。教科は自由入力なので世界史以外も追加可能。
- `pages/material.html`: 原本PDFの閲覧、ページ移動、25〜400%ズーム、2本指拡大操作、色表示設定。
- 管理者がPDFを選択して追加し、文字と「隠す範囲」を手動編集できる。オレンジ・赤・緑・黒の文字、大きさ、配置・範囲変更、削除、元に戻す・やり直すに対応。
- PDFの原本は変更せず、追加文字と範囲を別に重ねる。原本の赤／緑文字は手動で「隠す範囲」を作り、表示切り替えに対応させる。
- 公開中の内容と下書きを別保存。下書きを保存しただけでは公開中の内容は変わらず、「公開する」で反映。
- 教材の公開取り消し・アーカイブ・アーカイブ解除。アーカイブ解除は以前の公開状態も戻すため、操作前に確認を表示する。原本・学習記録・保存履歴は削除しない。
- ページ全体・追加した語句・手で囲んだ範囲を、既存の復習・個人メモ・共通メモへ登録できる。
- 一覧から教材のページ・登録座標へ移動できる。復習一覧の見出しは教材名とページのみで、答えを表示しない。
- 編集の未保存内容をアカウント別に端末のIndexedDBへ退避。保存失敗時は同じ操作IDで再送し、重複保存を防ぐ。別端末との競合は上書きせず表示する。

## 必要なCloudflare設定（既存のDB・認証設定は維持）

### 1. 原本PDFの保存先を作る

Cloudflareダッシュボード → R2 Object Storage → バケットを作成。
名前の例: `fullpuri-materials`。
公開アクセス・カスタムドメイン・r2.dev公開URLは有効にしない。APIトークンを新しく作ってフロントへ記載する必要はない。
R2の利用開始画面で契約・請求設定の確認が出た場合は、その画面に表示される条件を確認する。

### 2. 既存Workerへバインディングを追加

Workers & Pages → `fullpuri-review` → Bindings → Add binding → R2 bucket。
変数名を **`MATERIALS_BUCKET`** にし、作成したバケットを選択して保存する。
既存の `DB` バインディング、OAuth関連の変数・Secret、`ADMIN_USER_IDS` を変更しない。
管理者は既存の `ADMIN_USER_IDS=github:240299585` を使用する。既存GitHubアカウントへ連携したGoogleログインでも同じ権限になる。別に作成したGoogleアカウントは自動的には管理者にならない。

### 3. D1へテーブルを追加

既存D1 `fullpuri-review` のConsoleで
`assets/review/server/migrations/0005_materials_v15.sql`
を全体コピーして実行する。既存のテーブル・メモ・復習は消さない。

### 4. Workerを更新

既存 `fullpuri-review` の最新版のコード編集画面で、
`assets/review/server/worker_v15.mjs`
の内容全体へ置き換え、Deployする。これは単独で動くWorkerファイルで、追加importは不要。
Google／GitHubのClient Secret・Client ID・`SITE_URL`・`ADMIN_USER_IDS`・`DB`は今の設定を残す。

`https://fullpuri-review.niwatorikounotori.workers.dev/health`

### 5. サイト側の更新ZIPを適用

ZIPを**解凍せず** `_update_inbox` に1個だけ入れ、`更新パックを適用.bat` を実行する。

## 追加・編集の使い方

1. 教材ライブラリで管理者のアカウントへログイン。
2. 「教材を追加」を開いてPDF、教材名、教科、任意のフォルダーを指定。
3. 保存後、編集画面へ移動する。最初は非公開の下書き。
4. 文字を入力して色・サイズを選び、操作を「文字を追加」にする。PDF上で置く範囲を広めに囲む。
5. 元のPDFの赤／緑文字を隠したい場合は、該当の「隠す範囲」を選んで文字部分を囲む。
6. 編集項目をタップすると選択できる。文字・色・サイズを変えて「選択項目に適用」。位置変更は「選択項目の位置・大きさを変更」で新しい範囲を囲む。
7. 「下書きを保存」→「公開する」。公開前の下書きは管理者だけが見られる。
8. 公開画面では追加語句をタップ、または「範囲を囲む」で復習・メモに登録する。「ページ全体」でも登録できる。
9. 原本は「原本PDFを保存」で取得できる。

新規メモは従来どおり共通が初期値。個人を選択可能。共通と個人は別データで、コピーと削除の意味も従来どおり。
教材の非公開化後、一般ユーザーからその原本・共通メモ・共通メモ履歴へのAPIアクセスを拒否する。過去に自分が登録した復習と個人メモは保持し、自分の一覧で削除・復習完了できる。既に端末へダウンロードしたPDFを遠隔で消す機能はない。

## 保存方式と安全性

- 原本: 非公開R2。ファイルごとの固定ID・SHA-256で保存。元のバイト列を保持し、再圧縮・再画像化しない。
- 教材名・分類・追加文字・範囲・公開状態: D1 `materials`。
- 保存・公開の操作: `material_operations`。操作ID再送の整合性、管理者権限、期待する版番号を照合。
- 編集履歴: `material_history`。保存後の下書き・公開内容のスナップショットを保持。画面から操作日時・版番号を確認できる（過去版へのワンクリック復元は未実装）。
- 権限: Workerが既存のセッションからユーザーを特定し、サーバーの管理者設定と照合。ユーザーの自己申告ID・ブラウザの管理者フラグを信用しない。
- 一般ユーザーは公開された教材だけ閲覧できる。管理者のみ追加・編集・公開・アーカイブ可能。
- 復習・メモ: 既存のD1保存と端末間同期を使用。ページIDは `mat_<教材ID>_<ページ番号>`、位置は元PDFページに対する0〜1の比率。教材名の変更や倍率で位置・対象IDが変わらない。
- 編集の未送信内容はアカウント別に端末へ退避し、保存成功後に消去。これはバックアップ用で、永続保存先はR2とD1。
- バージョン競合時は入力を保持。「編集データを書き出す」「最新を読み直す」「入力を残して最新版に合わせる」で解決する。最後の操作は次回の保存でサーバーの下書きを置き換えるため確認を表示する。
- 公開は下書き保存の後に明示操作する。複数の管理者がいる場合、保存後に他の管理者が更新すれば版番号競合として拒否する。

## 今回の制限・未検証

- 原本PDFは1ファイル50MiB・1000ページまで。編集項目は教材全体1000件、編集JSON240KBまで。
- 新規PDFの自動OCR・自動的な色の認識、元PDF内のテキスト編集は未実装。色文字の追加・原文を隠す範囲は手動で設定する。元PDFの黒文字を文字列として直接選択する機能はなく、手動の範囲登録を利用する。
- パスワード付きPDF、PDFの差し替え、PDFへ追加文字を書き込んで書き出す機能は未対応。差し替えたい場合は新しい教材として追加する。
- 新規PDF内の横断OCR検索、既存の地域／時代／世紀分類への自動参加は対象外。教科・フォルダー・名前で教材ライブラリから探せる。
- 長期保管にはCloudflareのアカウント・R2・D1を継続して維持する必要がある。バケットの自動削除ルールは設定しない。
- 本番CloudflareでのR2実保存・デプロイ後の本番連携は未検証。バケットとD1はテスト用代替環境で検証。
- iPhone/iPad実機・Safari・Android実機は未検証。Chromiumで画面幅を再現した検証と実機確認は別。

## 検証結果

自動テスト81件成功。実際のWorker v15コードとSQLiteトリガーを使い、独立したDOM/IndexedDBクライアントで検証。

- 管理者以外の追加・編集・公開・削除操作をサーバー側で拒否。
- 下書き・アーカイブ中の原本とメモ履歴のアクセスを拒否。
- 公開済みの内容と編集下書きの分離、公開取り消し・再公開・アーカイブ解除。
- PDF原本のバイト一致、容量・SHA-256・形式・ページ数・範囲の検証。
- 操作の再送、応答だけ失われた場合の再送、別端末の版番号競合、入力保持・再読み込み・復元。
- 復習・メモ連携、履歴・復習回数・他アカウントからの個人データ分離。
- 既存世界史プリントの赤／緑／オレンジ、直接／タップ／非表示、範囲・黒文字登録、座標追従、既存復習・個人／共通メモ・Google連携の回帰確認。

ブラウザ: Chromium 153で実PDFをPDF.js 6.4.299で描画。
PC 1440×1000、スマホ相当390×664、iPad相当810×1080で、色表示切り替え・400%拡大・ページ復習・メモ保存・横方向のページはみ出しがないことを確認。スマホ相当のタッチ入力では範囲指定と2本指による拡大も確認。PCでは範囲を描いて文字追加→下書き保存→公開、実PDFの選択→読み込み→アップロード→編集画面への遷移も確認。
API・R2はテスト用に置き換え、ブラウザのFile送信はテスト用アダプターでバイト列として渡している。本番のネットワーク転送確認とは区別する。

## 本番設定後の確認

小さいPDFを1つ追加し、色文字を置いて保存・公開する。同じアカウントで別端末から教材を開き、復習・メモの相互反映を確認する。一般アカウントでは「教材を追加」「編集」が出ず、未公開教材のURL・原本APIへアクセスできないことも確認する。
