# 表示・ズーム高速化 v26

検証日: 2026-10-25。基準 main: `53d74216bddc6348869350e38ce01d2fd7d0a830`。

## 原因と修正

- `applyZoom` の幅変更で ResizeObserver が発火し、毎回アカウント操作・設定メニュー・語句衝突判定・メモレイヤーを再生成していた。サイズ変更は専用処理へ分離。保存座標の枠は従来通り百分率、余白アイコンも百分率で画像に追従させ、120ms静止後に余白配置だけを再計算する。設定やアカウントのDOMは触らない。
- メモなしの通常表示でも全語句を照合していたため、この走査を省略。
- 座標取得が認証サービス初期化の終了を待っていた。読み取り専用座標取得を先行し、認証→メモ初期化の順序は維持。同じNo.の座標要求は進行中も共有し、最大3件のLRUキャッシュと失敗時の再試行を実装。
- 原本画像を高優先度・非同期デコードとし、到着前から原寸の縦横比を確保。ページ選択肢の再生成を省略。キャッシュ済みの同じ画像でも読み込み表示を終了する。
- ピンチ中の基準幅測定を開始時1回にまとめ、同じ幅の書き込みを省略。従来の中心位置・スクロール計算、1フレーム1回の更新、25〜400%制限、終了時の最終フレーム反映は維持。
- No136–156の4ビューアには、表示画像と同時に前後3画像を取得する処理が残っていたため除去。新しい画像先読みは追加せず、表示中の画像を優先。

## 再実行

Node 24以上。`assets/review/tests`で`npm install --ignore-scripts`。`KOPURI_TEST_MODULES`を同ディレクトリの絶対パスへ設定して、リポジトリ直下で以下を実行する。

```text
node --experimental-vm-modules --test assets/review/tests/*.test.mjs
node _tools/performance_v26.cjs before-cpu
node _tools/performance_v26.cjs after-cpu
node _tools/browser_regression_v26.cjs
```

ブラウザ検証はPlaywrightとWindows Chromeを使用。`PLAYWRIGHT_MODULE`でPlaywrightのインストール先を指定できる。`AUTH_DELAY=1000`で認証応答遅延を再現できる。結果はリポジトリの隣の`qa_performance_v26`へ保存する。
